# Agent Note: 工作区侧栏统一 SVG 图标语言

Status: implemented

[English](2026-08-24-unified-workspace-sidebar-icons.md) | 中文

## 问题

工作区审查侧栏用 Unicode 字符充当 Git 变更、历史、执行环境、分支、提交操作和后台进程的伪图标。桌面工具栏使用行内 SVG，因此同一个面板混用了依赖字体的字符和矢量图标语言。字符的度量会随平台和皮肤变化，「本地」与「提交或推送」也容易看起来像互不相关的栏目，而不是同一组工作区控件。

## 决策

侧栏持有一个私有的 WorkspaceIcon 组件，使用封闭的名称联合类型和统一的 20px 描边处理。它为导航、刷新、添加、关闭、变更、历史、环境、分支、提交、进程和下拉箭头渲染行内 SVG，不新增图标依赖，也不改变共享皮肤 token。

执行环境、当前分支和 Git 操作现在以「副标签 + 主值」呈现。工作区目录和审查评论的关闭控件也使用同一套图标语言。既有的 Git 刷新、切换分支、提交、推送、评论、工作区选择和进程行为保持不变。

## 曾考虑的替代方案

**保留 Unicode 字符并调整字体。** 不采用：字符外观仍依赖安装字体、平台栅格化和皮肤排版，无法提供稳定的产品图标语言。

**引入第三方图标包。** 不采用：本界面只需要有限的一组简单图标，新增依赖会增加包体和另一套视觉事实来源，却不会删除有价值的代码。

**在视觉改版中同时重做工作区数据模型。** 不采用：当前歧义属于展示层。改变 Git 状态归属或变更契约会扩大风险，却不会改善本次目标。

## 后果

审查侧栏在不同桌面皮肤下拥有一致的图标几何，并且仓库事实与 Git 操作的分组更清楚。事实区因为每行增加副标签而略微变高。封闭的图标名称联合类型让后续新增图标必须显式发生，也让字符伪图标更容易在评审和测试中被发现。
